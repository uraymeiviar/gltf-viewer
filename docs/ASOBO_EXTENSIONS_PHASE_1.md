- [x] **A1.4 — `ASOBO_material_draw_order` (R2). Owner: Claude.**
  - **Rule (verified, SDK):** transparent objects sort back to front by the **mesh bounding-box centre**, not the
    pivot (MSFS SDK `flightsim-materials.md`, "Draw Order", line 371). Decals: the offset strictly specifies their
    order, higher drawn above/later, equal offsets keep back-to-front. Glass and windshield: `key = distance +
    offset`, drawn larger key first. Other material types ignore the value.
  - **Types:** decal = `ASOBO_material_geometry_decal` or `ASOBO_material_blend_gbuffer`; glass =
    `ASOBO_material_glass_v2` or `ASOBO_material_glass`; windshield = `ASOBO_material_windshield_v3` or
    `ASOBO_material_windshield`, all read from `renderer::Material::asobo`.
  - **Mechanism:** the offset is read once per material sync into `Material`; `createScene` sets the world
    bounding-box centre on `Mesh` and the per-viewport active flag when the asset declares the extension and
    `asoboOptions.applies(...)` is true. `CommandGenerator` copies class/offset into each `SortedCommand` and adds
    the glass offset to its key; `TransparentPass` draws decals first (offset ascending, then back to front) and
    every other blended draw by key. Covered transparent draws stop writing depth so their explicit order decides
    what is on top while they are forward blended; A2's deferred path replaces this. Files that do not declare the
    extension keep the previous pivot-distance order and depth writes byte for byte.
  - **Glass sign (inferred from the literal rule):** the SDK does not state which direction the offset moves a
    glass draw. The implementation uses the literal `key = distance + offset` with the existing larger-key-first
    transparent sort, so a positive glass offset acts like extra distance: it is drawn earlier, i.e. below other
    glass. Decals are the opposite convention: a higher offset is drawn later, above.
  - **Harness:** `scripts/validate_asobo_draworder.py` (quick tier, `run_regression.py`): a higher decal offset
    wins even when its quad is farther; equal offsets sort by the bounding-box centre (not the pivot); decals draw
    before glass; large/small glass offsets and windshield; an offset on a plain blended material is ignored with a
    byte-identical capture; switch off and an undeclared extension are byte-identical to the file without it.
  - **Results:** all harness checks PASS. `run_regression.py --extra=--asobo --extra=off` PASS. With ASOBO on, only
    the E195 cockpit cases differ: p8_1 (`e195` in all four AA modes), p8_3 (`e195`) and p8_5 (`e195`). E195
    `SCREEN_EICAS` on/off: the hazard-stripe decal placards around the pedestal knobs are fully visible with the
    switch on (mostly hidden without it), and a thin left screen-bezel line becomes visible; the EICAS glass itself
    looks the same in this dark frame.

- [x] **A1.9 — Packaged vertex data and windshield vertex colour.**
  - **Rule (measured, `ASOBO_VERTEX_COLOR_AND_PACKAGING.md` §1.2/§2.2/§2.3):** only files that declare `ASOBO_asset_optimized` use the package tool's vertex layout: `TEXCOORD_n` and `COLOR_0` in non-normalized SHORT/USHORT are IEEE half-floats; `NORMAL`/`TANGENT` in non-normalized BYTE are signed value / 127 (tangent w included); the 48-byte skinned layout's `COLOR_0` says BYTE but stores RGBA8, read unsigned / 255.
  - **Mechanism (vertex data):** `updateGltf` records `m_assetOptimized` from `extensionsUsed`. In the attribute setup in `GltfRenderLayer.cpp`, those accessors are handed to GL with the storage type: `GL_HALF_FLOAT` for the half-float TEXCOORD/COLOR attributes, `GL_BYTE` with `normalized = GL_TRUE` for NORMAL/TANGENT, and `GL_UNSIGNED_BYTE` with `normalized = GL_TRUE` for the skinned COLOR. The packaged `NORMAL` is `VEC4` with a 127 padding byte; it is defined and sized as `VEC3` so `primitive.vert` gets `HAS_NORMAL_VEC3`/`a_normal`, and when its bufferView has no stride the accessor's own 4-byte element stride is kept so the padding is skipped. No CPU conversion: positions (bounds, culling, picking are GPU or POSITION-based) are untouched. Primitives without `TANGENT` get generated tangents only when their material samples a normal map (A1.11); files that already store TANGENT are unchanged. Files without the declaration keep their accessor type and normalization byte for byte.
  - **Mechanism (windshield):** `updateMaterials` defines `ASOBO_MATERIAL_WINDSHIELD_V3` when the material declares the extension (declaration is filtered by `parseExtensions`). `getBaseColor()` returns the base colour before multiplying `COLOR_0` when `u_AsoboWindshieldVertexColorMask` is non-zero. That value is an `EnvironmentBlock` member uploaded per viewport from `vp->settings.asobo.applies("ASOBO_material_windshield_v3")`, exactly like A1.2's DirectX flag: the viewport switch is already in the redraw key and the value is a frame-block byte, so the command and uniform caches stay valid. The material-side decision is constant per asset, so the define does not vary by viewport.
  - **Mechanism (winding):** the packager stores every triangle clockwise, so a declared file needs clockwise as the front face (measured in `ASOBO_VERTEX_COLOR_AND_PACKAGING.md` §2.7: source 100% of 821,087 / 441,099 triangles agree with their normals, package 0% of 821,134 / 467,103). `GltfRenderLayer::updateMeshes` copies `m_assetOptimized` onto each `Mesh` as `assetOptimizedWinding`. `Mesh::effectiveFrontFace()` XORs it with the winding already decided for the node (`frontFace`, which carries the negative-determinant rule and the viewport's invert-winding override), so a mirrored packaged node cancels. `CommandMapping::makeCommand` is the single place that turns that into the draw command's `glFrontFace` state; opaque, transparent, the transmission copies, picking, the selection silhouette, wireframe and debug overlays all build through it. `gl_FrontFacing` follows `glFrontFace`, so the double-sided back-face normal flip stays correct. No CPU index reversal; undeclared files return `frontFace` unchanged.
  - **Support table:** `ASOBO_asset_optimized` is `Rendered` with a new `viewportSwitch = false` flag, so Viewport Settings lists no dead switch for it (the declaration selects both the vertex layout and the clockwise front face); `MSFT_texture_dds` is marked non-switchable for the same reason (its declaration, not the viewport, selects it). `ASOBO_material_windshield_v3` is `Partial`, note “vertex colour masks not used as colour; masks and windshield shading in A4”, so its switch appears.
  - **Harness:** `scripts/validate_asobo_packaged.py` (quick tier): the synthetic packaged copy is now stored with reversed (clockwise) indices. A declared clockwise copy must render like the float counter-clockwise quad (tolerance 10); the same clockwise copy without the declaration is culled and byte-identical to `a9c0a29`; a double-sided clockwise packaged quad seen from the back matches the source seen from the back; a declared file with a negative-scale (mirrored) node matches the source; a viewport click selects the packaged quad. `--asobo-disable ASOBO_asset_optimized` does not change the winding or the render. Real pairs use the same camera and all sibling `texture*` folders, and compare against a background capture at that camera: coverage of the source geometry (holes are package pixels that match the background, tolerance 2, must stay under 2%), mean colour and saturation. Windshield v3 with a red `COLOR_0` is byte-identical to the same quad without `COLOR_0`, `--asobo-disable ASOBO_material_windshield_v3` and `--asobo off` are byte-identical to `a9c0a29`, and a standard material keeps the tint.
  - **Results:** `scripts/validate_asobo_packaged.py` PASS; `scripts/validate_asobo_support.py` PASS. `run_regression.py --extra=--asobo --extra=off` PASS (`validate_asobo_common.py` now also disables `ASOBO_material_windshield_v3` in its all-rendered-extensions-off check). With ASOBO on, the differing suites are the E195 cockpit views (p8_1, p8_3, p8_5) because `ASOBO_material_windshield_v3` now keeps the red windshield masks out of base colour; the E190 exterior is byte-identical because the packaging layout is mandatory and no renderer-suite file declares it.
