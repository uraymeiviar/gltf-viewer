# Quality presets, Settings and runtime telemetry

The viewport quality dropdown offers Auto, Low, Mid, High and Ultra. Auto is the interactive default and gradually approaches the editable Ultra definition using the existing frame-time and memory controller. Its status text disappears when the configured target is reached. VRAM usage and FPS remain visible in the bottom status bar. Hover them for the accounting source, available memory, presentation/redraw rates and timing details; click either one to open and focus the Statistics panel.

Presets apply across viewports because uploaded textures and environment maps are shared. File → Settings contains Search Paths and Quality Presets tabs. Each quality definition can be edited independently, restored with Reset to default, or activated with Use this preset. Changes to the active preset apply immediately. Texture maximum changes re-decode and upload images without resetting the scene, selection, animation or edited material parameters. Raising the maximum restores retained source resolution where the memory budget allows it.

| Default | Texture maximum | Geometry/post AA | Environment | SSR / bloom | Grid |
|---|---|---|---|---|---|
| Low | 512 | Off / None | Skybox and IBL off; textured unlit preview when no debug view is selected | Off / off | Mesh plane |
| Med (Mid dropdown) | 1024 | 2x / None | IBL cube 512, 512 filtering samples | Off / off | Screen ray |
| High | 4096 | 2x / TAA | Full configured IBL | Medium / on | Screen ray |
| Ultra | Unlimited | 4x / TAA | Full configured IBL | High / on | Screen ray |

Punctual lights are enabled in these definitions. Med interprets the requested “no AA” as no post-AA alongside the explicitly requested MSAA 2x. Unlimited removes the preset texture cap and skips the estimate-based budget reduction; only the per-texture allocation fallback still protects against driver failures, so Ultra never reports a smaller clamp. Compressed KTX2 textures retain authored compressed mip levels, trimming larger levels when a smaller authored level is available. A chain without a sufficiently small authored level currently cannot guarantee the chosen cap; this edge remains recorded in the handoff journal.

Definitions, selection and the Auto switch persist in the portable `settings.ini` (`[QualityProfiles]` with `profile0.*` … `profile3.*` and `selection`, `[RenderQuality]` for the configured renderer values); only values that differ from the built-in defaults are written, using the same writable-directory fallback as the other settings. `--isolated` skips persistence. `--quality-preset auto|low|med|mid|high|ultra` selects the new definitions; existing `--quality high|balanced|performance` remains compatible. Capture/fixed-time/UI tooling suppresses adaptation unless explicitly requested. `--show-telemetry` exposes the new status metrics in tooling captures. Interactive sessions show them by default.

Search paths support case-insensitive `*` and `?` matching within directory components. `../texture*` finds sibling folders such as `texture.FSS`. `../*` includes immediate sibling directories. `../**` expands recursively, including the parent directory itself. Expansion is cached per model directory/configuration; reload rescans it. Symlinks and Windows reparse points are skipped to avoid directory cycles. Existing filename and extension fallback resolution runs inside the expanded folders.

Without a saved `[SearchPaths]` section, the list contains `../texture*` as an ordinary visible item with the same remove/order controls as any other path. It is not an implicit fallback. Removing the last item saves `[SearchPaths]` with `count=0`, preserving the empty list across restarts. Existing saved lists are kept as supplied; an absent section uses the default even when other settings exist. Re-adding the default-only list clears the override section. The glTF model's own directory remains the separate implicit first lookup.

Statistics has Overview, Textures and Meshes tabs. Overview includes DXGI local usage/budget/headroom, adapter capacity, shared memory, process peaks, physical/commit RAM, CPU frame mean/p95/max, process CPU utilization, GPU frame time and UI/render rates. GPU timing uses asynchronous timestamp queries and retains the last actual viewport render instead of replacing it with a cached-frame timing. CPU timing includes application frame orchestration; it is not a CPU profiler. Presented FPS and rendered FPS differ when the viewport reuses a cached image.

Texture rows show mapped resident GL payload, dimensions/mip count, decoded CPU data and retained encoded bytes. Mesh rows deduplicate base attribute/index accessor buffers within each mesh. Shared buffers may appear in more than one mesh row. Generated tangents, morph/skin resources, driver padding and allocation overhead are not assigned to these per-mesh figures. Resource totals are payload estimates and need not equal OS GPU accounting. Unknown GPU metrics remain explicitly unknown. Inspectors also expose the texture/mesh payload estimates.

Implementation entry points are `RenderQuality.cpp` (profiles/controller/persistence), `SearchPathsPanel.cpp` (Settings), `AppSettings.cpp` (wildcard cache), `RuntimeTelemetry.h` / `MemoryInfo.h` / `ResourceMemory.h` (samples and accounting), and the status/statistics/inspector panels. `scripts/check_quality_controls.py` exercises the new controls using generated private assets and a private settings directory. See `QUALITY_CONTROLS_HANDOFF.md` for current validation state and remaining work; original loading measurements are reported separately.
